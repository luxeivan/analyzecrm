Роль: Ты — Senior Full-Stack разработчик и эксперт по Data Engineering. Твоя задача — спроектировать и написать код для проекта по глубокому анализу данных из Битрикс24.

Контекст и вводные данные:
- Источник данных: Облачный Битрикс24 (доступ через входящий вебхук).
- Объем данных: ~51 000 компаний и ~103 000 контактов. Данные объемные, с большим количеством кастомных полей (UF_*), множественных полей (телефоны, email, реквизиты) и справочников (enum).
- Текущая проблема: Данные в CRM запутаны, нужен удобный интерфейс для их визуализации, связывания (контакты <-> компании) и анализа.
- Ограничения API Битрикс24: 
  - Лимит выдачи: 50 записей за 1 запрос.
  - Ограничение по времени: 1 запрос не дольше 60 секунд.
  - Rate Limit: примерно 2 запроса в секунду (нужны задержки, чтобы не получить 503 или блокировку).
  - Пагинация: использовать метод `start=-1` и фильтр `>ID` для оптимизации.
  - Кастомные поля не приходят по умолчанию, нужно делать `crm.contact.fields` / `crm.company.fields`, забирать оттуда `UF_*` и передавать их в `select`.

Твоя задача — пошагово написать полный проект. Разбей работу на 4 шага (фазы) и выдавай код строго по мере завершения предыдущего шага.

### Фаза 1: Инфраструктура (Docker Compose)
Напиши `docker-compose.yml`, который поднимает:
1. **PostgreSQL** (основная база данных). Обязательно подключи расширение `pgvector` (для будущей работы с ИИ-эмбеддингами).
2. **Adminer** или **pgAdmin** (для удобного просмотра БД).
3. **Node.js контейнер** (для ETL-скрипта выгрузки и Backend API).
4. **React (Vite) контейнер** (для Frontend).
Опиши переменные окружения, volumes и сеть (network).

### Фаза 2: ETL-скрипт выгрузки (Node.js)
Напиши скрипт на Node.js (`axios` + `pg`), который выкачивает данные и пишет их напрямую в PostgreSQL (не в JSON, чтобы не сожрать оперативную память!).
Требования к скрипту:
1. **Создание схемы БД:** Скрипт должен создавать таблицы в Postgres. Предложи оптимальную схему (сырые данные в `JSONB` для гибкости + нормализованные таблицы для быстрого поиска).
2. **Пагинация и лимиты:** Реализуй функцию `fetchAll`, которая использует `start=-1`, сортировку `ORDER: { ID: 'ASC' }`, фильтр `>ID` и `await sleep(500)` между запросами. Добавь retry-логику (3 попытки при ошибке сети/503).
3. **Сбор всех полей:** Сначала скрипт запрашивает метаданные полей, извлекает все ключи `UF_*` и добавляет их в `select: ['*', ...userFields]`.
4. **Пакетная вставка:** Данные из API (по 50 штук) нужно сразу отправлять в БД батчами (bulk insert), а не копить в массиве.
5. **Справочники:** Напиши логику, как скрипт будет выкачивать значения для полей типа `enumeration` (справочники), чтобы потом можно было заменить ID на человекочитаемый текст.

### Фаза 3: Backend API (Node.js + Express/NestJS)
Напиши API, который будет отдавать данные для дашборда.
Требования:
1. **Эндпоинты для аналитики:** Получение списка контактов/компаний с фильтрацией, пагинацией и поиском.
2. **Эндпоинт для связей:** Возврат графа связей (Компания -> Контакты -> Сделки) для визуализации.
3. **Агрегация:** Эндпоинт, который считает статистику (например, сколько компаний в каждом регионе, сколько контактов без компании).
4. **ИИ-интеграция:** Эндпоинт, который формирует краткую выжимку (JSON) по конкретному клиенту, чтобы этот JSON можно было скормить локальной LLM для анализа.

### Фаза 4: Frontend (React + TypeScript + TailwindCSS + Recharts)
Напиши интерфейс для визуализации.
Требования:
1. **Дашборд:** Графики (круговая диаграмма по сегментам клиентов, барчарт по источникам).
2. **Таблица данных:** Мощная таблица с возможностью поиска по любым полям, фильтрации по справочникам и сортировки.
3. **Карточка клиента:** При клике на компанию открывается карточка, где виден полный профиль, все кастомные поля (расшифрованные) и привязанные контакты.
4. **Связи:** Визуализация графа связей (можно использовать `react-force-graph` или `vis-network`), чтобы видеть, как контакты привязаны к компаниям и сделкам.

Начни с **Фазы 1**. Напиши `docker-compose.yml` и структуру папок проекта. Жди моего подтверждения, прежде чем переходить к написанию кода ETL-скрипта (Фаза 2).
